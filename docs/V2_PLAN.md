# VERDANT 2.0 — аудит и технический план

## 1. Аудит (что уже было)

**Стек.** Next.js 15 (App Router) + React 19 + TypeScript, Tailwind v4, framer-motion; свой `server.ts` (tsx) — Next и WebSocket на одном порту; PostgreSQL через Prisma 6; Redis (ioredis) — лимиты запросов, онлайн, общий Crash, джекпот; zod для проверки входных данных. Деплой — Docker на Render (`render.yaml`, `docker/start.sh`: `prisma migrate deploy` → seed → сервер).

**Игры (21).** Слоты: Avalanche, Neon Burst, Crystal Vault, Emerald Cases, Atlas of Stars, Neon Garden. Быстрые: Crash (общий раунд, WebSocket), Mines, Tower, Dice, Plinko, Limbo, Wheel, Keno, Coinflip, Roulette, Race. Карточные: Blackjack, Video Poker, Baccarat, Hi-Lo. Все исходы считает сервер по схеме provably fair (HMAC-потоки), раунды можно проверить на `/fair`.

**Авторизация.** Почта+пароль (scrypt), сессии в БД (в cookie только токен, в БД — SHA-256), CSRF-токен в заголовке и проверка Origin, блокировка после неудачных входов, восстановление пароля, демо-гости (живут 3 дня), вход через Telegram Mini App с проверкой подписи `initData` на сервере.

**Баланс.** `Wallet` + неизменяемый журнал `LedgerEntry`; единственная точка изменения — `applyEntry` (ключ идемпотентности уникален, списание атомарно проверяет остаток); `withUserTx` блокирует строку кошелька (`FOR UPDATE`). Есть сверка «баланс = сумма журнала».

**Уже было:** кабинет (обзор, история операций журнала, настройки, сеансы, удаление аккаунта), админка (обзор, пользователи, корректировка баланса, роли, блокировка, игры: лимиты/вкл, сессии, журнал действий, настройки платформы, пополнения), турнир недели (лучший множитель, призы, автоматическая выплата раз в 15 минут), сундук с ключами и джекпотом, ежедневный бонус, избранное (только в localStorage), поиск и вкладки в каталоге.

**Найденные проблемы и долг.**
- На главной блок «Недавно играли» — жёстко заданный список, а не реальные данные игрока.
- «Популярное» — тоже фиксированный список, без статистики.
- Избранное хранилось только в браузере — терялось при смене устройства.
- Нет таблицы ошибок: падения API видны только в логах Render.
- Демо-касса имитировала банковские способы оплаты (СБП / карта / кошелёк, «банк обрабатывает»), а валюта показывалась как «₽» — это противоречит правилу «только виртуальные демо-рубли, без маскировки под финансовые операции».

## 2. Архитектура новых функций

**Новые таблицы** (одна миграция `20261106000000_v2_platform`, существующие данные не трогаются):
`Favorite`, `ActivityDay`, `AchievementDef`/`UserAchievement`, `QuestDef`/`UserQuest`, `Notification`, `Tournament`/`TournamentEntry`, `ErrorLog`; новые поля `User.prefs`, `Game.category`, `Game.addedAt`; новый тип журнала `REWARD`.

**Движок прогресса** (`src/server/progress`). Метрики считаются только на сервере из таблиц раундов и активности: сыграно раундов, побед, разных игр, дней активности, лучший множитель, поставлено; дневные — раунды за сегодня, разные игры и категории за сегодня, новая игра, визит. После каждой ставки или выигрыша игрок помечается «изменившимся», фоновый обработчик (раз в 2 с) проверяет достижения и задания. Награда за достижение начисляется сразу, за задание — по кнопке «Забрать». Обе операции идут через `applyEntry` с уникальным ключом (`ach:…`, `quest:…:день`), строки `UserAchievement`/`UserQuest` имеют составной первичный ключ — повторное начисление невозможно.

**Сутки и недели** — по Москве (как у существующего турнира).

**Турниры.** Настройки (вкл/выкл, призы, минимальная ставка) хранятся в `Setting`. Итоги прошедшей недели фиксируются в `Tournament`/`TournamentEntry` (топ-50), участники получают уведомления; в начале недели — уведомление о старте.

**Уведомления** — таблица `Notification`; колокольчик в шапке с числом непрочитанных, отметка прочитанного.

**Админка** — новые разделы: операции (журнал всех кошельков), достижения, задания, турниры, ошибки; категория игры в разделе «Игры». Все маршруты закрыты серверной проверкой роли (`route({ auth: "ADMIN" | "SUPPORT" })`).
