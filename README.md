# Verdant — демонстрационная платформа мини-игр

Только виртуальные баллы: их нельзя купить или вывести. Реальные платежи не подключены и не планируются без лицензии.

## Стек
Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · Framer Motion · PostgreSQL + Prisma · Redis (rate limiting, realtime) · WebSocket (Crash, этап 6)

## Структура
```
prisma/            схема БД, миграции, seed
src/app/           страницы и API-маршруты (app/api/*)
src/components/    UI: shell, auth, account, games, ui
src/server/        серверная логика: auth, wallet (журнал баланса), games (provably fair), security
src/lib/           общие утилиты клиента (api, форматирование, список игр)
```

## Запуск
```
cp .env.example .env        # впиши пароль БД и APP_SECRET
npm install
npx prisma migrate deploy
ADMIN_PASSWORD=... npm run db:seed
npm run build && npm start  # http://localhost:3000
```

## Готово (этапы 1–5)
- Регистрация, вход, выход, восстановление пароля (ссылка пока пишется в лог сервера — почтовый сервис подключается отдельно)
- Пароли: scrypt; сессии: httpOnly-cookie, в БД только SHA-256 токена; CSRF-токен + проверка Origin; блокировка после 5 неверных паролей; rate limiting в Redis
- Кабинет: баланс, ежедневный бонус, статистика, сверка баланса с журналом; история операций с фильтрами; настройки (ник, аватар, пароль, сеансы)
- Баланс меняется только через журнал `LedgerEntry` с уникальным ключом идемпотентности и атомарной проверкой остатка
- Журнал действий `AuditLog`

## Быстрый запуск на Windows

1. Установи Docker Desktop и запусти его.
2. Распакуй архив и дважды кликни `start-docker.bat`.
3. Сайт откроется на http://localhost:3000. Админ: `admin@verdant.local`, пароль — `ADMIN_PASSWORD` в файле `.env`.

## Этап 6 — игры

| Игра | Как считается результат | Где |
|---|---|---|
| Dice | бросок 0,00–100,00, множитель = (100 − преимущество) / шанс | `src/server/games/instant.ts` |
| Limbo | множитель = (1 − преимущество) / (1 − x), выигрыш если ≥ цели | там же |
| Plinko | 8/12/16 рядов, 3 уровня риска, путь шарика — по числу на ряд | там же, таблицы в `src/lib/fair/outcomes.ts` |
| Roulette | европейская, 37 секторов, ставки на число/цвет/дюжину/колонку и т.д. | там же |
| Mines | поле 5×5, 1–24 мины, расстановка тасованием Фишера — Йетса; можно забрать после любой клетки | `src/server/games/mines.ts` |
| Crash | общий раунд в реальном времени: WebSocket `/ws/crash`, события через Redis pub/sub, автовывод | `src/server/crash/*`, `server.ts` |

- Результаты считает только сервер: HMAC-SHA256(серверный сид, «клиентский сид:nonce:cursor»).
- Хэш серверного сида виден до игры. Сид раскрывается при смене пары (`/fair`), для Crash — сразу после обвала.
- Страница `/fair` пересчитывает любой раунд прямо в браузере (WebCrypto), теми же функциями, что и сервер.
- Все ставки идут через журнал баланса с ключом идемпотентности. Операции одного игрока выполняются по очереди: кошелёк блокируется через `SELECT … FOR UPDATE`.
- Цикл Crash ведёт один экземпляр сервера (блокировка-лидер в Redis). Если сервер перезапустился посреди раунда, раунд отменяется, ставки возвращаются.

Запуск: `npm run dev` (разработка) или `npm run build && npm start`. Next.js и WebSocket работают на одном порту через `server.ts`.
Тесты: `npm test` — 8 юнит-тестов формул и генератора (RTP, равномерность, совпадение браузерного и серверного HMAC).

## Этап 7 — админ-панель (`/admin`)

Доступ проверяется на сервере. Для игрока раздел отдаёт 404, каждый API-маршрут проверяет роль.

| Раздел | Поддержка (SUPPORT) | Администратор (ADMIN) |
|---|---|---|
| Обзор: пользователи, сессии, ставки/выплаты, RTP по играм, график за 14 дней, сверка «кошельки = журнал» | ✓ | ✓ |
| Пользователи: поиск, карточка, журнал баланса, раунды, события | ✓ | ✓ |
| Блокировка/разблокировка с причиной (сессии сбрасываются), завершение сессий | только игроков | игроков и поддержки |
| Смена роли игрок ⇄ поддержка, корректировка демо-баланса | — | ✓ |
| Игры: включение, лимиты ставок, преимущество, название, порядок | просмотр | ✓ |
| Активные сессии с устройством и IP, завершение | ✓ | ✓ |
| Журнал действий с фильтрами | ✓ | ✓ |
| Настройки: техработы, регистрация, стартовые баллы, бонус, объявление | просмотр | ✓ |

- Менять свой аккаунт и пользователей своего уровня или выше нельзя.
- Каждое действие пишется в журнал (`admin.*`).

## Этап 8 — интеграция бэкенда

- `GET /api/health` проверяет БД, Redis и цикл Crash. Этим маршрутом пользуются healthcheck в Docker и Render.
- Раз в час удаляются просроченные сессии и использованные ссылки сброса пароля.
- По SIGTERM сервер останавливается корректно. Оборванный раунд Crash при следующем старте отменяется, ставки возвращаются.
- Адрес сайта берётся из `APP_URL`, `RENDER_EXTERNAL_URL` или `SPACE_HOST`. От него зависят флаг Secure у cookie и ссылки в письмах.

## Этап 9 — тесты

- `npm test`: юнит-тесты формул и генератора.
- `npm run test:e2e`: 53 сквозные проверки API на запущенном сервере. Проверяются вход, CSRF/Origin, все игры, параллельные ставки, идемпотентность, пересчёт раундов по раскрытым сидам, Crash через WebSocket, права ролей, блокировки, техработы и журнал.
  Пример: `BASE_URL=http://localhost:3000 ADMIN_PASSWORD=… npm run test:e2e`.
- Индексы: `Round(gameSlug, settledAt)` для ленты игроков, `Round(userId, createdAt)`, `LedgerEntry(userId, createdAt)`, `Session(expiresAt)`.

## Этап 10 — размещение

**Свой сервер (VPS):**
```bash
cp .env.example .env    # задать POSTGRES_PASSWORD, ADMIN_PASSWORD, APP_URL=https://твой-домен
docker compose up -d --build
```
HTTPS настраивается обратным прокси (Caddy/Nginx). WebSocket `/ws/crash` должен проксироваться с заголовками Upgrade.

**Render (бесплатно, из GitHub):** New → Blueprint → репозиторий. `render.yaml` создаст веб-сервис, PostgreSQL и Redis. Пароль админа сгенерируется в переменной `ADMIN_PASSWORD`.

**Платежи:** в `src/server/payments` лежит только изолированный интерфейс. Единственная реализация — «выключено». Модуль не подключён ни к API, ни к интерфейсу. Подключать реальные деньги можно только при лицензии и юридической проверке.

## Слоты и редизайн

- **«Атлас звёзд»**: книжный слот 5×3 на 10 линий. Книга-атлас работает как wild и как скаттер: 3+ книги дают 10 бесплатных вращений с особым символом, который раскрывается на весь барабан. Бонус можно купить за 51× ставки. RTP ≈ 95,5%.
- **«Неоновый сад»**: 5×4 на 25 линий, джокер на барабанах 2–4. 3+ символа BONUS дают 10 бесплатных вращений, в которых все выигрыши умножаются на ×3; повторные 3 BONUS добавляют ещё 10 вращений. Бонус можно купить за 26× ставки. RTP ≈ 95,8%. Раунды, сыгранные до этой версии (с пятью бонусами), новым движком не пересчитываются.
- В обоих слотах есть «интрига»: если на первых барабанах уже 2 бонус-символа, остальные барабаны крутятся дольше и подсвечиваются. Автоигра запускается и без лимита.
- Движки слотов лежат в `src/lib/fair/slots.ts` и работают одинаково на сервере и в браузере. Серия бесплатных вращений целиком считается в одном раунде из потока HMAC, поэтому её можно проверить на странице `/fair`.
- Графика: обложки, баннеры, фоны и символы сгенерированы моделью FLUX.1-schnell (`public/img`). Цифры и буквы на барабанах нарисованы кодом.
- Новый дизайн: фиолетово-розовая палитра, слайдер баннеров, бегущая лента выигрышей, разделы «Слоты» и «Оригинальные игры», у каждой игры своя обложка и цвет.
