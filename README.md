# Verdant — демонстрационная платформа мини-игр

Только виртуальные демо-рубли: их нельзя купить или вывести. Реальные платежи не подключены и не планируются без лицензии.

## Стек
Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS 4 · Framer Motion · PostgreSQL + Prisma · Redis (rate limiting, realtime) · WebSocket (Crash, этап 6)

## Структура
```
prisma/            схема БД, миграции, seed
src/app/           страницы и API-маршруты (app/api/*)
src/components/    UI: shell, auth, account, games, ui
src/server/        серверная логика: auth, wallet (журнал баланса), games (provably fair), security
src/lib/           общие утилиты клиента (api, форматирование, список игр)
```

## Запуск
```
cp .env.example .env        # впиши пароль БД и APP_SECRET
npm install
npx prisma migrate deploy
ADMIN_PASSWORD=... npm run db:seed
npm run build && npm start  # http://localhost:3000
```

## Готово (этапы 1–5)
- Регистрация, вход, выход, восстановление пароля (ссылка пока пишется в лог сервера — почтовый сервис подключается отдельно)
- Пароли: scrypt; сессии: httpOnly-cookie, в БД только SHA-256 токена; CSRF-токен + проверка Origin; блокировка после 5 неверных паролей; rate limiting в Redis
- Кабинет: баланс, ежедневный бонус, статистика, сверка баланса с журналом; история операций с фильтрами; настройки (ник, аватар, пароль, сеансы)
- Баланс меняется только через журнал `LedgerEntry` с уникальным ключом идемпотентности и атомарной проверкой остатка
- Журнал действий `AuditLog`

## Быстрый запуск на Windows

1. Установи Docker Desktop и запусти его.
2. Распакуй архив и дважды кликни `start-docker.bat`.
3. Сайт откроется на http://localhost:3000. Админ: `admin@verdant.local`, пароль — `ADMIN_PASSWORD` в файле `.env`.

## Этап 6 — игры

| Игра | Как считается результат | Где |
|---|---|---|
| Dice | бросок 0,00–100,00, множитель = (100 − преимущество) / шанс | `src/server/games/instant.ts` |
| Limbo | множитель = (1 − преимущество) / (1 − x), выигрыш если ≥ цели | там же |
| Plinko | 8/12/16 рядов, 3 уровня риска, путь шарика — по числу на ряд | там же, таблицы в `src/lib/fair/outcomes.ts` |
| Roulette | европейская, 37 секторов, ставки на число/цвет/дюжину/колонку и т.д. | там же |
| Mines | поле 5×5, 1–24 мины, расстановка тасованием Фишера — Йетса; можно забрать после любой клетки | `src/server/games/mines.ts` |
| Crash | общий раунд в реальном времени: WebSocket `/ws/crash`, события через Redis pub/sub, автовывод | `src/server/crash/*`, `server.ts` |

- Результаты считает только сервер: HMAC-SHA256(серверный сид, «клиентский сид:nonce:cursor»).
- Хэш серверного сида виден до игры. Сид раскрывается при смене пары (`/fair`), для Crash — сразу после обвала.
- Страница `/fair` пересчитывает любой раунд прямо в браузере (WebCrypto), теми же функциями, что и сервер.
- Все ставки идут через журнал баланса с ключом идемпотентности. Операции одного игрока выполняются по очереди: кошелёк блокируется через `SELECT … FOR UPDATE`.
- Цикл Crash ведёт один экземпляр сервера (блокировка-лидер в Redis). Если сервер перезапустился посреди раунда, раунд отменяется, ставки возвращаются.

Запуск: `npm run dev` (разработка) или `npm run build && npm start`. Next.js и WebSocket работают на одном порту через `server.ts`.
Тесты: `npm test` — 8 юнит-тестов формул и генератора (RTP, равномерность, совпадение браузерного и серверного HMAC).

## Этап 7 — админ-панель (`/admin`)

Доступ проверяется на сервере. Для игрока раздел отдаёт 404, каждый API-маршрут проверяет роль.

| Раздел | Поддержка (SUPPORT) | Администратор (ADMIN) |
|---|---|---|
| Обзор: пользователи, сессии, ставки/выплаты, RTP по играм, график за 14 дней, сверка «кошельки = журнал» | ✓ | ✓ |
| Пользователи: поиск, карточка, журнал баланса, раунды, события | ✓ | ✓ |
| Блокировка/разблокировка с причиной (сессии сбрасываются), завершение сессий | только игроков | игроков и поддержки |
| Смена роли игрок ⇄ поддержка, корректировка демо-баланса | — | ✓ |
| Игры: включение, лимиты ставок, преимущество, название, порядок | просмотр | ✓ |
| Активные сессии с устройством и IP, завершение | ✓ | ✓ |
| Журнал действий с фильтрами | ✓ | ✓ |
| Настройки: техработы, регистрация, стартовые демо-рубли, бонус, объявление | просмотр | ✓ |

- Менять свой аккаунт и пользователей своего уровня или выше нельзя.
- Каждое действие пишется в журнал (`admin.*`).

## Этап 8 — интеграция бэкенда

- `GET /api/health` проверяет БД, Redis и цикл Crash. Этим маршрутом пользуются healthcheck в Docker и Render.
- Раз в час удаляются просроченные сессии и использованные ссылки сброса пароля.
- По SIGTERM сервер останавливается корректно. Оборванный раунд Crash при следующем старте отменяется, ставки возвращаются.
- Адрес сайта берётся из `APP_URL`, `RENDER_EXTERNAL_URL` или `SPACE_HOST`. От него зависят флаг Secure у cookie и ссылки в письмах.

## Слоты и редизайн

- **«Атлас звёзд»**: книжный слот 5×3 на 10 линий. Книга-атлас работает как wild и как скаттер: 3+ книги дают 10 бесплатных вращений с особым символом, который раскрывается на весь барабан. Бонус можно купить за 51× ставки. RTP ≈ 95,5%.
- **«Неоновый сад»**: 5×4 на 25 линий, джокер на барабанах 2–4. 3+ символа BONUS дают 10 бесплатных вращений, в которых все выигрыши умножаются на ×3; повторные 3 BONUS добавляют ещё 10 вращений. Бонус можно купить за 26× ставки. RTP ≈ 95,8%. Раунды, сыгранные до этой версии (с пятью бонусами), новым движком не пересчитываются.
- В обоих слотах есть «интрига»: если на первых барабанах уже 2 бонус-символа, остальные барабаны крутятся дольше и подсвечиваются. Автоигра запускается и без лимита.
- Движки слотов лежат в `src/lib/fair/slots.ts` и работают одинаково на сервере и в браузере. Серия бесплатных вращений целиком считается в одном раунде из потока HMAC, поэтому её можно проверить на странице `/fair`.
- Графика: обложки, баннеры, фоны и символы сгенерированы моделью FLUX.1-schnell (`public/img`). Цифры и буквы на барабанах нарисованы кодом.
- Новый дизайн: фиолетово-розовая палитра, слайдер баннеров, бегущая лента выигрышей, разделы «Слоты» и «Оригинальные игры», у каждой игры своя обложка и цвет.

## «Мастерская Санты»: слот с сундуками

- 5×4 на 25 линий, Дед Мороз — wild на барабанах 2–4. Символы — сгенерированный арт (FLUX.1-schnell): леденец, варежка, пряник, какао, снежный шар, щелкунчик.
- Пять раскрашенных сундуков с полукруглой крышкой стоят на горе золотых монет в шахматном порядке: 3 спереди, 2 сзади. На каждом значок его бонуса.
- Монеты пяти цветов (золотой гурт и эмаль со значком) падают на барабаны и улетают в сундук своего цвета. Горка монет в сундуке растёт, но числа монет игрок не видит.
- Когда сундук наполняется, бонус запускается сам: из сундука и с золотой горы сыплются монеты, появляется заставка. Дальше игрок проходит бонус сам: выбирает подарки, запускает каждое вращение, перекрут и колесо. Автоигра на бонусе останавливается. Призы определены при спине, чтобы раунд можно было пересчитать на `/fair`; порядок нажатий сумму не меняет.
- Каждая монета с шансом 10% наполняет сундук до краёв: иногда хватает 1 монеты, иногда нужно 30 и больше. Шанс у монет одинаковый, поэтому сундук «не помнит» прошлых монет и поднимать ставку под полный на вид сундук бессмысленно. Бонус считается от текущей ставки.
- Пять бонусов, по одному на сундук:
  - **Подарки** — открыть 3 подарка из 12;
  - **Мороз** — 10 вращений с примерзающими Дедами Морозами;
  - **Звездопад** — 10 вращений, множитель +1 после каждого выигрыша;
  - **Колокольчики** — колокольчики с номиналами и 3 перекрута, всё поле даёт ×200;
  - **Колесо** — от ×5 до ×250.
- Состояние сундуков хранится в таблице `SlotMeter`, по строке на игрока. Ставка и сундуки обрабатываются в одной транзакции под блокировкой кошелька.
- Состояние сундуков до спина записывается в параметры раунда, поэтому раунд можно пересчитать на `/fair`.
- RTP ≈ 95,5%, подобран симуляцией на 4 млн спинов. Бонус в среднем раз в ~58 спинов.

## Карточка игры и демо-вход

- Нажатие на игру (карточка в каталоге, боковое меню, лента выигрышей) открывает карточку игры, а не саму игру. В карточке обложка, описание, RTP, лимиты ставки и сердечко «в избранное». На телефоне карточка выезжает снизу.
- Избранное хранится в браузере и показывается во вкладке «❤️ Избранное» каталога.
- Гость видит две кнопки: «Демо» и «Играть».
  - «Демо» создаёт временный аккаунт `guest_xxxxxx@guest.local` с демо-рублями и сразу открывает игру.
  - «Играть» ведёт на регистрацию и после неё возвращает в игру (`?next=`).
- Вошедший игрок видит одну кнопку «Играть».
- Гостевые аккаунты удаляются фоновой задачей через 3 дня, вместе с кошельком, журналом и раундами (каскадом).
- Лимит гостевых входов — 10 в час с одного IP.

## Карточные игры, гонка, акции и новое лобби

**Новые игры** (логика — чистые функции в `src/lib/fair/cards.ts`, проверяются на `/fair`):
- **Блэкджек у камина** — бесконечная колода, дилер стоит на 17 и проверяет блэкджек, блэкджек 3:2, удвоение, один сплит (тузы — по одной карте). Удвоение и сплит списывают ещё одну ставку отдельной записью журнала; закрытая карта дилера не отдаётся клиенту, пока раунд идёт. RTP ≈ 99,3% (Монте-Карло, 2 млн раздач по базовой стратегии). Для проверки ходы записываются строкой (`hsdp`).
- **Снежный покер** — видеопокер «валеты и выше», таблица 9/6 (RTP 99,54% при оптимальной игре). Колода без повторов: первые 10 позиций тасования — раздача и запасные карты; запасные скрыты до замены.
- **Баккара** — классические правила третьей карты; Игрок 1:1, Банкир 0,95:1, Ничья 8:1 (RTP 98,8–98,9%). Фишки на три поля, ставка — их сумма.
- **Гонка на санях** — 5 саночников с шансами 36/26/18/12/8%, выплата `(1 − преимущество) / шанс`.

**Акции** (страница `/bonuses`, все призы — демо-рубли):
- **Снежные ключи и сундук.** За любую ставку от 1 ₽ с шансом 1/40 выпадает ключ (сервер, `crypto.randomInt`, хук в `applyEntry`). 4 ключа открывают сундук: приз 50–2 500 ₽ или весь джекпот (шанс 1%). 0,5% каждой ставки пополняет джекпот (Redis, база 25 000 ₽). Ключи — в шапке, новый ключ показывается всплывающим сообщением.
- **Турнир недели «Ледяная гонка».** С понедельника 00:00 МСК; очки — лучший множитель одного выигрыша со ставкой от 1 ₽. 10 призовых мест; призы начисляет фоновая задача (ключ журнала `tour:<неделя>:<место>` и уникальность `(week, place)` исключают двойную выплату). Демо-гости не участвуют.
- Новый тип записи журнала `PROMO`, таблицы `PromoState` и `PromoWin` (миграция `promo_keys_tournament`).

**Лобби:** полки игр со стрелками (Популярные, Новинки, Слоты, Карточные, Быстрые), карточки джекпота и турнира на главной, два новых слайда с таймером, лента выигрышей с уровнями (Большой ×10, Огромный ×25, Мега ×50, Легендарный ×100), вкладки каталога со счётчиками.

## Telegram Mini App

Сайт работает как приложение внутри Telegram: бот с кнопкой «Играть», вход в один тап без пароля.

**Подключение (5 минут):**
1. В Telegram открыть [@BotFather](https://t.me/BotFather) → `/newbot` → придумать имя и username бота → получить токен.
2. Render → сервис `verdant` → **Environment** → добавить переменную `TELEGRAM_BOT_TOKEN` с этим токеном → Save (сервис перезапустится).
3. Готово: при старте сервер сам ставит вебхук, кнопку меню «Играть», команды `/start`, `/games`, `/help` и описание бота.
4. (Необязательно) BotFather → бот → *Bot Settings → Configure Mini App* → указать адрес сайта — появится ссылка `t.me/<бот>?startapp=blackjack`, открывающая сразу нужную игру.

**Как устроено:**
- `src/server/telegram/initData.ts` — проверка подписи данных запуска (HMAC-SHA256 от токена бота, срок 24 ч). Подделать вход без токена нельзя.
- `POST /api/auth/telegram` — находит или создаёт аккаунт по Telegram ID (почта `tg_<id>@telegram.local`, ник из username Telegram); если внутри Telegram уже выполнен вход в обычный аккаунт — привязывает Telegram к нему.
- Cookie сессии из Telegram — `SameSite=None; Partitioned`, чтобы работало и в Telegram Web (там сайт открыт во фрейме). Встраивать сайт разрешено только Telegram (`frame-ancestors`).
- `POST /api/telegram/webhook` — сообщения боту, принимаются только с секретным заголовком, который сервер сам передал в `setWebhook`.
- `TelegramBridge` — SDK Telegram грузится только внутри Telegram: цвета шапки, системная кнопка «Назад», вибрация при нажатии «Играть» и при выигрыше, переход в игру по `startapp`.
- На сайте появляется карточка «Verdant в Telegram», когда бот подключён.

## Пополнение баланса (демо-касса)

Стартовых денег при регистрации больше нет (`startGrant` = 0, меняется в админке → Настройки). Баланс пополняется на странице `/deposit` (кнопка «+» рядом с балансом):

- от **300 до 300 000 ₽** за раз, не больше **1 000 000 ₽** за 24 часа;
- способы СБП / карта / кошелёк — только оформление: деньги не списываются, данные карты не запрашиваются;
- повторный клик с тем же ключом не пополняет дважды; каждое пополнение — запись `DEPOSIT` в журнале баланса и строка в таблице `Deposit`;
- админка → «Пополнения»: суммы за сутки, неделю и всё время, средний чек, последние 50 пополнений.

Код: `src/server/wallet/deposit.ts`, `src/app/api/account/deposit`, `src/components/wallet/DepositPage.tsx`. Подключение реального платёжного провайдера к игровой платформе требует лицензии оператора — см. `src/server/payments/index.ts`.

## Приватность и защита данных

- **IP-адреса не хранятся.** Вместо адреса — метка `ip-…` (HMAC с секретом сервера): по ней нельзя восстановить IP, но видно, что два аккаунта заходили с одного адреса. Метка используется и в ключах лимитов. Адрес клиента берётся из заголовков прокси хостинга (`cf-connecting-ip` / `true-client-ip`), подделать его своим `X-Forwarded-For` нельзя. Секрет — `DATA_SECRET` (если не задан — производный от `DATABASE_URL`).
- **Браузер не сохраняется** — только тип устройства («Chrome · Android»).
- **Публичные ленты** (выигрыши, раунды, Crash, турнир) показывают только ник и аватар. Сотрудники (поддержка, админы) и игроки с **анонимным режимом** — «Скрытый игрок». Сотрудники в турнире не участвуют.
- **Telegram:** ник нового игрока случайный (`player_xxxxxx`), username и имя из Telegram нигде не используются.
- **Поддержка** видит почту замаскированной (`k***@gmail.com`) и не может искать по почте. Полную почту видит только администратор.
- **Перебор:** вход и регистрация не подтверждают, существует ли почта; несуществующий логин блокируется после 5 попыток так же, как настоящий. Админ-API для игрока отвечает 404, как будто его нет.
- **Логи** хостинга не содержат почт и ссылок восстановления пароля. Журнал действий хранится 90 дней.
- **Удаление аккаунта** — в настройках (ник + пароль): аккаунт и все его данные удаляются каскадом.
- **Заголовки:** `Referrer-Policy: no-referrer`, HSTS, строгая CSP, `frame-ancestors` только Telegram, без `X-Powered-By`; личные разделы закрыты от поисковиков. Сторонних счётчиков и трекеров нет.
